# Правила ручной разметки эталона

Эталон должен перечислять **все** клинические утверждения в оцениваемых страницах документа,
а не только интересные примеры (иначе Precision занижается, Recall завышается).

## Что размечать

Одно утверждение = одно клиническое действие или факт:

* результаты исследования (различия, частоты, эффекты, осложнения) — `study_finding`;
* явные рекомендации авторов («should», «we recommend», «is indicated», «рекомендуется») — `source_recommendation`;
* определения, классификации, эпидемиология, патогенез, клиническая картина, прогностические факторы — `background_fact`.

Пересказ чужих работ («по данным X и соавт. [12]») размечается, но с пометкой `"secondary": true`.

## Что НЕ размечать

Ссылки на литературу, благодарности, конфликты интересов, описание дизайна и методов
(«пациенты рандомизированы», «использован тест»), цели исследования, исходные характеристики
выборки (средний возраст, исходное смещение), планы будущих исследований.

## Поля утверждения

```json
{
  "page": 1,                       // порядковый номер страницы PDF (с 1), не печатный номер
  "category": "treatment",         // background | diagnosis | treatment | rehabilitation | prevention | organization | other
  "polarity": "conditional",       // positive | negative | conditional | descriptive
  "age_group": "children",         // adults | children | mixed | unspecified
  "key_params": "старше 10 лет; полное смещение",   // существенные условия, дозы, пороги, сроки
  "statement_ru": "…",             // русская формулировка
  "quote": "…"                     // дословная цитата на языке источника
}
```

Полярность: `negative` — вмешательство не эффективно / вредно / не рекомендуется; `conditional` —
только при условии; «нет статистически значимых различий» — `descriptive`.

## Правило сопоставления с результатом системы

Совпадают: клиническое действие или факт, группа пациентов, направление утверждения и
существенные условия. Расхождение в дозе, пороге, возрастной группе или отрицании — **ошибка**
(near miss). Сопоставление «один к одному»: перефразы не увеличивают число найденных утверждений.

## Лишние карточки

Карточка системы, не сопоставленная с эталоном, не считается ошибкой автоматически. После оценки
создаётся `data/eval/<проект>_extras_for_review.csv`: эксперт ставит в колонке `expert_valid`
«да» (допустимое утверждение, пропущенное в эталоне) или «нет». Повторный запуск с
`--extras-review` даёт скорректированную Precision.

## Файл эталона

`gold/<имя>.json` — см. пример `gold/example_gold_p1.json`. Поле `pages: [from, to]` ограничивает
оцениваемые страницы: карточки системы с других страниц в оценку не входят.

> `gold/example_gold_p1.json` — пример для отладки (черновая разметка стр. 1 трёх статей,
> подготовлена ассистентом и требует проверки командой). Для итоговых метрик используется выданный
> преподавателем эталон; эталон итогового набора не используется для настройки.
