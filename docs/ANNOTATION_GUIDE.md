# Правила разметки эталона

Эталон перечисляет **все** клинические утверждения на оцениваемых страницах документа, а не только
интересные. Если размечать выборочно, точность получится заниженной, а полнота завышенной.

## Что размечать

Одно утверждение — одно клиническое действие или факт:

- результаты исследования (различия, частоты, эффекты, осложнения) — `study_finding`;
- явные рекомендации авторов («should», «we recommend», «is indicated», «рекомендуется») —
  `source_recommendation`;
- определения, классификации, эпидемиология, патогенез, клиническая картина, прогностические
  факторы — `background_fact`.

Пересказ чужих работ («по данным X и соавт. [12]») тоже размечается, с пометкой `"secondary": true`.

## Что не размечать

Ссылки на литературу, благодарности, конфликты интересов, описание дизайна и методов («пациенты
рандомизированы», «использован тест»), цели исследования, исходные характеристики выборки (средний
возраст, исходное смещение), планы будущих исследований.

## Поля утверждения

| Поле | Значение |
|---|---|
| `page` | порядковый номер страницы в PDF, с 1 (не печатный номер) |
| `category` | `background`, `diagnosis`, `treatment`, `rehabilitation`, `prevention`, `organization`, `other` |
| `polarity` | `positive`, `negative`, `conditional`, `descriptive` |
| `age_group` | `adults`, `children`, `mixed`, `unspecified` |
| `key_params` | существенные условия, дозы, пороги, сроки, например «старше 10 лет; полное смещение» |
| `statement_ru` | формулировка по-русски |
| `quote` | дословная цитата на языке источника |

Полярность: `negative` — вмешательство не эффективно, вредно или не рекомендуется; `conditional` —
только при условии; «нет статистически значимых различий» — `descriptive`.

## Как результат сопоставляется с эталоном

Утверждения совпадают, если совпадают клиническое действие или факт, группа пациентов, направление
утверждения и существенные условия. Расхождение в дозе, пороге, возрастной группе или отрицании —
это ошибка, а не совпадение. Сопоставление один к одному: перефразы одного утверждения не
увеличивают число найденных.

## Лишние факты

Факт программы, которого нет в эталоне, не считается ошибкой автоматически. После оценки создаётся
`data/eval/<проект>_extras_for_review.csv`: в колонке `expert_valid` ставится «да» (утверждение
верное, его просто нет в эталоне) или «нет». Повторный запуск с `--extras-review` даёт уточнённую
точность.

## Файл эталона

`gold/<имя>.json`, пример — `gold/example_gold_p1.json`. Поле `pages: [from, to]` у документа
ограничивает оцениваемые страницы. Для полноты кандидатами служат все факты документа (утверждение
из аннотации может быть извлечено со страницы результатов), а в точность идут факты размеченных
страниц и совпавшие с эталоном.

`gold/example_gold_p1.json` — разметка стр. 1 трёх статей для отладки. Итоговые метрики считаются по
полной разметке.
