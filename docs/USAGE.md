# Как пользоваться KRGen

## Запуск

```bash
python -m krgen.server
```

Открыть http://127.0.0.1:8765. Если модель отвечает «OAuth session expired» — выполнить `claude auth login`.

## Демонстрация (новый прогон + готовый результат)

Вкладка **«Прогоны»**:
* **Новый прогон** — отметить 1–2 короткие статьи → «▶ Запустить новый прогон». Создаётся отдельная
  копия проекта, обработка идёт в фоне, прогресс и журнал видны прямо в таблице; исходный проект не меняется.
  Если статьи уже обрабатывались, библиография и извлечение берутся из кэша; проверка, группировка
  и тезисы выполняются заново (у копии свои идентификаторы карточек) — около 1–2 минут на короткую
  статью, ~$0.2 эквивалента.
* **История прогонов** — у каждого завершённого прогона сохраняется снимок результата: цифры
  (документы, карточки, тезисы, повторы, противоречия, запросы, стоимость), журнал этапов,
  черновик и кнопки скачать Word / Markdown / JSON. «Перейти к проекту» — открыть живые карточки и тезисы.

Сценарий для преподавателя: запустить новый прогон на 1–2 статьях → пока он идёт, открыть в
истории готовый прогон проекта `demo` и показать результат.

## Рабочий цикл

1. **Проект.** «+ Проект»: тема, возрастная группа, коды МКБ-10, организация. (Демо-проект `demo` уже создан.)
2. **Документы.** Перетащить PDF. Сразу видно: число страниц, дубликаты, сканы без текста.
3. **▶ Обработать.** Идёт в фоне; в шапке — этап и прогресс. Галочки:
   «LLM-рецензент» (смысловая проверка, лучше не выключать) и «только сбойные фрагменты» (после сбоя API).
4. **Документы** после обработки: статус (обработан / частично / без результатов / ошибка) и полоса
   страниц — зелёная обработана, голубая — список литературы, серая — вне бюджета длинного документа.
5. **Карточки доказательств** — главная рабочая вкладка эксперта. Фильтр «требует проверки» →
   открыть карточку → прочитать формулировку, цитату и подсвеченную страницу справа → посмотреть
   проверки (✅ пройдено, ⚠️ на проверку, ☑️ эвристика снята рецензентом, ❌ цитата не найдена) →
   «Подтвердить» / «Отклонить» / поправить поля / «Объединить с…».
6. **Противоречия** — обе стороны с цитатами; записать решение (стороны не удаляются).
7. **Тезисы** — по разделам 103н. Править текст, вводную фразу, УДД/УУР (становятся решением эксперта),
   критерий качества; «Утвердить». Флаги ⚠ объясняют, что требует решения. Вверху вкладки — форма экспертного тезиса.
8. **Обработать ещё раз** после правок карточек: перепроверка и пересборка тезисов. Правки не
   теряются; если автоматика предлагает другое — появится жёлтый блок «Принять новую / Оставить мою».
9. **Черновик и экспорт** — предпросмотр и выгрузка Word, Markdown, JSON (полный и по схеме преподавателя).
10. **Отчёт** — покрытие, запросы, токены, стоимость, ошибки, метрики по эталону.
11. **Журнал правок** — все решения эксперта.

## Командная строка (эксперименты и пакетная обработка)

| Задача | Команда |
|---|---|
| Обработать проект | `python -m krgen.cli run demo` |
| Выгрузить всё в папку | `python -m krgen.cli export demo out` |
| Оценка по эталону | `python -m krgen.evaluate demo gold/example_gold_p1.json` |
| Эксперимент | `python -m krgen.experiment experiments/thinking_and_gate.json` |
| Демонстрация сбоя | `KRGEN_FAIL_AFTER=5 python -m krgen.cli run demo` |
