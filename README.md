# KRGen

KRGen собирает клиническую рекомендацию (КР) по приказу Минздрава России № 103н из научных статей
в PDF. Из статей извлекаются отдельные факты с дословными цитатами, каждый факт проверяется по тексту
PDF, проверенные факты группируются, противоречия между ними нормируются, и уже из нормированных
фактов собирается КР: разделы 1–7, тезисы с УДД и УУР, критерии качества, список литературы.
Результат выгружается в Word, Markdown и JSON.

Рабочая версия: https://test.savkin.xyz (вход по паролю).

## Как идёт обработка

PDF разбирается сразу при загрузке (`pdf_ingest.py`): текст по страницам, поиск дубликатов,
разметка страниц со списком литературы и страниц без текстового слоя.

Кнопка «Обработать» (или `python -m krgen.cli run <проект>`) запускает этапы по порядку. Ими
управляет `run_project()` в [krgen/pipeline.py](krgen/pipeline.py).

1. **keywords** (`extract.py`) — ключевые слова темы на русском и английском. По ним выбираются
   страницы длинных документов.
2. **extract** (`extract.py`, `pdf_ingest.py`) — библиография статьи (название, год, дизайн
   исследования, DOI), поиск дубликатов по DOI и названию, нарезка текста на фрагменты по 1–3
   страницы и извлечение фактов. Модель сначала копирует дословную цитату, потом пишет формулировку
   по-русски и заполняет поля: раздел КР, группа пациентов, вмешательство, доза, сроки и т. д.
3. **verify** (`verify.py`, `textnorm.py`) — проверка фактов. Код ищет цитату на странице и сверяет
   числа, единицы, знаки и отрицания, затем модель-рецензент проверяет, подтверждает ли цитата
   формулировку. Итог: подтверждён, на проверке или не подтверждён.
4. **group** (`groups.py`) — подтверждённые факты одного раздела КР собираются в группы фактов,
   которые утверждают одно и то же, у каждой группы своя формулировка. Здесь же ищутся противоречия.
   Код не даёт смешать в одной группе детей и взрослых или противоположные выводы.
5. **resolve** (`resolve.py`) — противоречия нормируются по правилам, без модели. Разные группы
   пациентов — остаются обе стороны; иначе выигрывает сторона с лучшим УДД или с большим числом
   независимых источников; при равной силе решает эксперт.
6. **kr** (`synth.py`) — сборка КР из групп. Для разделов 2–6 пишется по тезису на группу
   («Рекомендуется …»), для разделов 1.1–1.6 и 7 — абзацы текста. УДД, УУР и вводную фразу считает код.

В конце сохраняется снимок результата (`snapshots.py`), он виден в истории прогонов. Документ КР
и выгрузки строит `export.py`.

Кнопка «Собрать КР заново» запускает только group, resolve и kr: после решений эксперта КР
пересобирается без повторного извлечения. Разделы, где факты не менялись, берут группировку из
кэша ответов модели.

### Какие факты попадают в КР

- Факт подтверждён проверкой (`verified`) или экспертом. Факты «на проверке» не используются, пока
  эксперт их не подтвердит.
- Эксперт его не отклонил, документ не помечен дубликатом, факт относится к теме.
- Факт не на проигравшей стороне противоречия. Обе стороны противоречия с решением «Исключить оба»
  и обе стороны нерешённого противоречия в КР не идут.
- Группа факта не исключена экспертом.

Это три функции: `live_facts()` в `groups.py`, `excluded_fact_ids()` в `resolve.py` и
`kr_evidence()` в `synth.py`. Тезис, у которого не осталось ни одного такого факта, в КР не
выводится (кроме тезисов, добавленных экспертом вручную).

## Окна интерфейса

| Окно | Адрес | Что там |
|---|---|---|
| 1. Документы | `#/p/<проект>/pdf` | загрузка PDF, статус каждого файла, число фактов |
| 2. Факты | `#/p/<проект>/facts` | список фактов с фильтрами; у факта цитата, страница PDF с подсветкой, результаты проверок, кнопки «Подтвердить», «Отклонить», «Изменить» |
| 3. Группы и противоречия | `#/p/<проект>/groups` | противоречия: стороны A и B, предложенное решение, кнопки выбора; ниже группы фактов по разделам КР |
| 4. Клиническая рекомендация | `#/p/<проект>/kr` | документ по 103н, правка тезисов, выгрузка в Word, Markdown, JSON |

Ещё есть «История» (`#/p/<проект>/history`): прошлые прогоны с цифрами, журналом этапов и файлами
снимка. Адреса можно открывать напрямую, кнопки браузера «назад» и «вперёд» работают.

## Быстрый старт

Нужны Python 3.11+ и Claude Code CLI с входом по подписке Claude. API-ключ не нужен.

```bash
pip install -r requirements.txt
claude auth login
python -m krgen.server
```

Открыть http://127.0.0.1:8765, создать проект, загрузить PDF и нажать «Обработать». По шагам —
в [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md), консольные команды — в [docs/USAGE.md](docs/USAGE.md).

Сквозной тест с заглушкой вместо модели (подписка не расходуется, нужны `311.pdf` и `588.pdf` в
папке `Статьи Разбор клинреков`):

```bash
python tests/test_pipeline_stub.py
```

## Настройки

Модель — `claude-haiku-5-5` через Claude Agent SDK, уровень рассуждений `low`. Все запросы идут
через `call_json()` в [krgen/llm.py](krgen/llm.py): там кэш ответов, проверка JSON по схеме,
повторы при сбое и учёт токенов.

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KRGEN_MODEL` | `claude-haiku-5-5` | модель для извлечения, группировки и сборки КР |
| `KRGEN_JUDGE_MODEL` | `claude-haiku-5-5` | модель-рецензент |
| `KRGEN_EFFORT` | `low` | уровень рассуждений: `low`, `medium`, `high` |
| `KRGEN_JUDGE_EFFORT` | `low` | то же для рецензента |
| `KRGEN_CONCURRENCY` | `4` | сколько запросов к модели идёт параллельно |
| `KRGEN_DATA` | `./data` | папка с базой, загрузками, кэшем и снимками |
| `KRGEN_CLAUDE_CLI` | `claude` из PATH | путь к Claude Code CLI |
| `KRGEN_FAIL_AFTER` | не задано | тестовый сбой: после N запросов модель «отказывает» |

Остальные параметры задаются в `config.json` в корне (образец — `config.example.json`, поля — как в
классе `Settings` в [krgen/config.py](krgen/config.py)): размер фрагмента `chunk_chars` (9000),
лимит страниц на документ `max_pages_per_doc` (60), пороги поиска цитаты `quote_fuzzy_threshold`
(90) и `quote_partial_threshold` (75), фактов на запрос рецензента `judge_batch` (15), фактов на
запрос группировки `cluster_batch` (45).

Смена модели, уровня рассуждений или промпта меняет ключ кэша, и прогон пойдёт заново за счёт
подписки.

## Данные

Всё хранится в `data/` (на сервере — `/var/lib/krgen`), в репозиторий папка не входит:

| Путь | Что |
|---|---|
| `krgen.sqlite` | база: проекты, документы, страницы, фрагменты, факты, группы, противоречия, тезисы, журнал правок, запросы к модели, прогоны |
| `llm_cache/` | кэш ответов модели |
| `uploads/` | копии загруженных PDF |
| `snapshots/` | снимки прогонов: Word, Markdown, JSON, сводка |
| `eval/`, `experiments/` | результаты оценки по эталону и экспериментов |

```

  pipeline.py     порядок этапов, статусы документов, отчёт об обработке

  verify.py       проверка фактов: цитата, числа, отрицания, рецензент
```
